# Retrospective

## Overview

This project involved creating a Software Quality Handbook using a collaborative GitHub workflow. The team focused not only on producing strong content, but also on following trunk-based development practices such as feature branches, pull requests, and peer reviews.

Overall, the project was successful in combining technical content creation with real-world development practices.


## What Went Well

- **Clear project structure and planning**  
  The project plan helped break the work into manageable tasks and ensured that each team member had clear responsibilities.

- **Effective use of Git and GitHub workflow**  
  The team consistently used feature branches, pull requests, and merges into the main branch. This kept the repository organised and reduced the risk of conflicts.

- **Strong collaboration between team members**  
  Each topic had at least two contributors, and team members reviewed each other’s work through pull requests. Feedback was used to improve content before merging.

- **Use of diagrams to improve clarity**  
  Adding visuals such as workflows and the Test Pyramid made the handbook easier to understand and more professional.

- **Incremental commits and updates**  
  Work was committed in stages rather than all at once, which provided a clear history of progress and development.
