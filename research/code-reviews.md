# Code Reviews - Research

## Source 1 - Google Engineering Practices

Link: https://google.github.io/eng-practices/review/

Notes:
- Code reviews are essential for maintaining code quality
- Reviews should focus on correctness, readability, and maintainability
- Reviewers should be respectful and constructive
- Small, frequent reviews are more effective than large ones

Key Insight:
Code reviews are most effective when they are small, frequent, and focused on improving the overall quality of the code


## Source 2 - Atlassian

Link: https://www.atlassian.com/agile/software-development/code-reviews

Notes:
- Code reviews help catch bugs early before production
- They promote knowledge sharing across the team
- Pull requests should be reviewed quickly to avoid delays
- Large pull requests are harder to review effectively

Key Insight:
Fast and consistent code reviews improve both code quality and team collaboration


## Source 3 - Martin Fowler

Link: https://martinfowler.com/articles/on-pair-programming.html

Notes:
- Code review is a key practice in improving software quality
- Feedback should focus on improving the solution, not criticising the developer
- Collaborative review practices improve team learning
- Developers benefit from seeing how others approach problems

Key Insight:
Code reviews are not just about finding bugs but also about sharing knowledge and improving team skills

## Common Themes

- Small pull requests are easier and more effective to review
- Code reviews should be done quickly to avoid blocking progress
- Reviews should be constructive, not overly critical
- Code reviews improve knowledge sharing within teams
- Large or poorly described changes reduce review quality
