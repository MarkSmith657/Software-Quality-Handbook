# Testing - Research 

## Source 1 – ISTQB (International Software Testing Qualifications Board)

Link: https://www.istqb.org/

Notes:
- Testing is used to evaluate whether a system meets requirements
- It helps identify defects before software is released
- Testing should be planned early in the development lifecycle
- Different levels of testing exist (unit, integration, system, acceptance)

Key Insight:
Testing is a structured process that ensures software quality by identifying defects and validating requirements at different stages

## Source 2 – Martin Fowler

Link: https://martinfowler.com/bliki/TestPyramid.html

Notes:

- Introduces the concept of the Test Pyramid
- Emphasises having more unit tests than UI tests
- Lower-level tests are faster and more reliable
- Over-reliance on UI tests leads to slow and fragile test suites

Key Insight:
A balanced testing strategy (Test Pyramid) improves efficiency, reliability, and maintainability

## Source 3 – Atlassian

Link: https://www.atlassian.com/continuous-delivery/software-testing

Notes:

- Testing should be integrated into the development workflow
- Continuous testing supports continuous integration and delivery
- Automated testing improves speed and consistency
- Manual testing is still important for exploratory testing

Key Insight:
Combining automated and manual testing leads to more effective and continuous quality assurance

## Source 4 – Google Testing Blog

Link: https://testing.googleblog.com/

Notes:

Emphasises automation and scalability in testing
Encourages small, fast, and independent tests
Test reliability is critical for large systems
Flaky tests reduce trust in the testing process

Key Insight:
Reliable and maintainable tests are more valuable than simply having a large number of tests

## Source 5 – Microsoft Testing Guidelines

Link: https://learn.microsoft.com/

Notes:

- Testing should align with user requirements and real-world usage
- Test cases should cover both expected and edge-case scenarios
- Good documentation improves test repeatability
- Testing should be risk-based, focusing on critical functionality

Key Insight:
Effective testing focuses on real user scenarios and prioritises high-risk areas

## Common Themes

- Testing should be integrated early in development
- Automation improves speed and consistency
- A balanced testing approach is essential (Test Pyramid)
- Tests must be reliable and maintainable
- Both functional and edge-case scenarios should be covered
- Testing is continuous, not a one-time phase
