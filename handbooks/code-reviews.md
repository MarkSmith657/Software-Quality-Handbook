# Code Reviews

## Introduction

Code reviews are a key practice in maintaining software quality within a development team. They involve examining code changes before they are merged into the main codebase, helping to identify bugs, improve readability, and ensure consistency across the project.

In fast-moving teams, code reviews also play an important role in knowledge sharing and collaboration. However, like estimation, the effectiveness of code reviews depends heavily on how they are carried out. Poorly managed reviews can slow down development, reduce team morale, and lead to superficial feedback.

From the research, it is clear that the most effective code reviews are those that are small, timely, and focused. Teams tend to struggle when pull requests are too large, reviews are delayed, or feedback becomes overly critical. When done properly, code reviews not only improve code quality but also strengthen team communication and shared understanding.

## Best Practices

- **Keep pull requests small and focused**  
  Smaller changes are easier to review and understand. This allows reviewers to give more meaningful feedback and reduces the chance of missing issues.

- **Review code promptly**  
  Timely reviews help maintain development flow and prevent bottlenecks. Delays in reviewing can slow down progress and disrupt team productivity.

- **Focus on important issues first**  
  Reviews should prioritise correctness, readability, and maintainability rather than minor stylistic concerns.

- **Be constructive and respectful in feedback**  
  Feedback should aim to improve the code, not criticise the developer. A positive tone encourages collaboration and learning.

- **Provide clear context in pull requests**  
  Descriptions should explain what the change does and why it was made. This helps reviewers understand the purpose of the code more quickly.

- **Use code reviews for knowledge sharing**  
  Reviewing code helps team members learn from each other and understand different parts of the system.

## Poor Practices to Avoid

- **Submitting large pull requests**  
  Large changes are difficult to review effectively and often lead to missed issues or shallow feedback.

- **Delaying code reviews**  
  Slow reviews can block progress and create frustration within the team.

- **Focusing too much on minor details**  
  Spending too much time on small stylistic issues can distract from more important problems in the code.

- **Providing overly critical or negative feedback**  
  Harsh feedback can reduce morale and discourage team members from engaging in the review process.

- **Reviewing without proper context**  
  If a pull request lacks explanation, reviewers may misunderstand the changes or miss important details.

- **Trying to review too much at once**  
  Reviewing large amounts of code in one session reduces effectiveness and increases the likelihood of errors being missed.
